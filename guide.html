Client KM Logbook · iPhone setup

Install the logbook
on your iPhone

This is a static, offline-capable Home Screen web app. Trips, clients, and the rate are saved in this app’s storage on your iPhone. There is no account, backend, or external database.

Safari installation requires one HTTPS address. iPhone Safari adds a Home Screen app from a page opened at a website URL. The package cannot be installed directly from a Windows folder or the iPhone Files app. The address only serves the app files; trip data is not uploaded. If you do not want the app files hosted anywhere, this Safari installation method cannot be used.

1. Put the static files at an HTTPS address

One simple option is GitHub Pages. It serves the app files without a database or application server. Do not upload trip records or JSON backups.

  1. On your Windows computer, open github.com and sign in or create an account.
  2. Create a new repository. Set it to Public, give it a name such as client-km-logbook, and create it.
  3. Choose Add file → Upload files. Upload the contents of the client-km-pwa folder, keeping the icons folder intact. The repository root must contain index.html, manifest.webmanifest, and service-worker.js.
  4. Commit the uploaded files. Open the repository’s Settings → Pages.
  5. Under Build and deployment, choose Deploy from a branch, select main and /(root), then save.
  6. Wait for the published address shown on the Pages settings screen. It will look like https://your-name.github.io/client-km-logbook/.
Privacy: the published files contain only the app, not your records. The app saves trips in IndexedDB and local storage for its Home Screen origin. It makes no data upload requests.

Keep the repository limited to the app files. Your JSON backup and Excel exports contain private trip information and belong in the iPhone Files app, not in GitHub.

On your iPhone

2. Install from Safari

  1. Make sure the iPhone is online. Open Safari and enter the HTTPS address from GitHub Pages.
  2. Wait for the logbook dashboard to load. Leave it open online for about a minute so the offline app files can be cached.
  3. Tap Safari’s Share button, then choose Add to Home Screen. If it is hidden, scroll down in the share sheet or edit its actions.
  4. Leave Open as Web App turned on, tap Add, then open the new KM Logbook icon from the Home Screen.
  5. After the first load, the app shell is cached and the logbook can open without a connection. Use the Home Screen icon for your logbook so it uses the same saved data each time.
Moving existing records: the Home Screen app has its own storage and does not automatically inherit records from another browser or an older local copy. Before switching, export a JSON backup from the old logbook. In the installed app, open Export & backup → Restore from a backup file and select that JSON file from Files.

3. Save a trip and review your dashboard

  1. Open Add trip, enter the date, trip type, from/to clients, and either kilometres or odometer readings.
  2. Tap Save trip. The record is stored on the iPhone. The second save button carries the destination and odometer reading into the next trip leg.
  3. Open Dashboard. Choose a financial year and a month. The cards show totals for the selected month or whole financial year; the tables show monthly and daily totals.
  4. Use Trip log to filter individual records by year and month. The logbook uses Australian July–June financial years.

Backups and files

Keep a backup in Files

  1. Open Export & backup and tap Download backup file.
  2. In Safari’s download prompt or share sheet, choose Save to Files, then save the JSON file somewhere you can find again, such as On My iPhone or iCloud Drive.
  3. To recover records, use Restore from a backup file and choose the JSON file in the iOS file picker. Restoring merges records with the ones already stored.
  4. Use the Excel export buttons for a real .xlsx workbook. Save that file to Files or open it in a spreadsheet app.
Back up regularly. iOS may remove website storage under some conditions, and removing the Home Screen app or its website data can remove its local records. A backup in Files is the recovery copy.

If the app does not open offline

  • Open the HTTPS address in Safari once while connected, wait for the page to finish loading, then reopen the Home Screen icon.
  • Check that the static host serves service-worker.js, manifest.webmanifest, and the files under icons from the same folder as the app.
  • Do not clear Safari website data for the app’s address. If the files have changed, reopen the address while online to receive the updated app.

Apple’s documented flow is Safari → open a website → Share → Add to Home Screen. Storage is local to the web app origin; keep a separate JSON backup.
